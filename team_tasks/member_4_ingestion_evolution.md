# Member 4 — Lead Ingestion, Workflows & Evolution

## Goal
Implement CSV ingestion, allowlisted workflow actions, analytics and human-approved evolution proposals.

## Read first
- `AGENTS.md`
- `docs/API_CONTRACTS.md`
- `backend/app/schemas/crm.py`

## Scope
- Implement CSV upload for a CRM entity using the documented multipart endpoint.
- Normalize headers, validate each row against CRM field metadata and report row-level errors.
- Add duplicate detection if time allows; document the matching rule.
- Implement workflow create/list/execute using allowlisted trigger/action types only.
- Compute analytics from persisted records; document the conversion-rate definition.
- Generate evolution proposals using computed metrics as evidence.
- Implement approve/reject endpoints with authorization, audit logging, version checks and idempotent behavior where practical.
- Add tests for malformed CSV, invalid rows, workflow validation and stale proposals.

## CSV import requirements
- Enforce file size and row-count limits (document the limits in code and API contract).
- Validate every row against the CRM entity's field definitions:
  - Reject unknown fields.
  - Reject missing required fields.
  - Validate field types and select options.
  - Sanitize values to prevent CSV formula injection and XSS.
- Enforce the same authorization rules as manual record creation:
  - Verify CRM ownership before import.
  - Records are created with the CRM's `owner_id`.
- Return `ImportResult` with `imported`, `skipped`, and `errors` counts per row.
- Log import operations with user ID, CRM ID, timestamp, and summary statistics.

## Evolution proposal requirements
- Create proposals with `status: "pending"`.
- Include evidence from computed analytics or observed events (e.g., "Conversion rate dropped from 15% to 10%").
- **Never apply proposals automatically**. Proposals remain pending until an authorized user approves.
- Revalidate proposals at approval time:
  - Check that referenced workflows/entities still exist.
  - Verify the proposal is not stale (configuration hasn't changed).
  - If stale, mark as `"stale"` and return `409 CONFLICT`.
- Record approval/rejection events in an audit log:
  - `proposal_id`, `crm_id`, `user_id`, `action` (approve/reject), `timestamp`, `reason` (for rejections).
- Make approval idempotent: repeated approval requests for the same proposal return the same result.

## WhatsApp integration (optional)
- WhatsApp integration is **optional** and should not block core CSV import and evolution approval flows.
- If implementing, use the WhatsApp Business API with proper webhook verification.
- Document message templates and rate limits.

## Do not
- execute arbitrary code or SQL generated by the LLM.
- activate AI-generated workflows without explicit authorization.
- fabricate analytics evidence or claim an improvement was measured without before/after data.
- make WhatsApp integration a blocker for the core demo.

## Acceptance criteria
- CSV import returns imported/skipped counts and row errors.
- Only allowlisted workflow actions can be created or executed.
- Proposals remain pending until an authorized user approves them.
- Approval revalidates the proposal and records an audit event.
